# Контракт в TypeSpec и цепочка кодогенерации

Контракт API — единственный источник правды и описан в TypeSpec, из него генерируется OpenAPI. Клиентский SDK для фронта генерирует `@hey-api/openapi-ts` (пиним точную версию: пакет 0.x с частыми ломающими релизами), сервер потребляет тот же OpenAPI через `fastify-openapi-glue` на рантайме — отдельного кодогенера для серверных типов не заводим.

## Considered Options

- **`openapi-typescript`** для серверных типов — отклонён: ломается на TypeScript 7 (падает на `ts.factory`, несовместим с нативным компилятором).
- **OpenAPI Generator** для сервера — отклонён: нет генератора под Fastify.
- **`@hey-api/openapi-ts`** для клиента — принят и запинен, потому что даёт typed fetch-клиент + типы + (опционально) валидационные схемы одной командой.

## Consequences

- Сгенерированное (`apps/web/src/client`, `apps/api/generated/openapi.yaml`) коммитится и не правится руками; ESLint исключает сгенерированный SDK.
- Server-side валидация запросов и маршруты приходят из OpenAPI через `fastify-openapi-glue` в `apps/api/src/app.ts`. Обработчики — заготовки, пока фича-тикеты не заполнят их. Отдельных сгенерированных `.ts` для сервера нет.
- `pnpm generate` повторяет всю цепочку одной командой.
